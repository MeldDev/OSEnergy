# Казино для MCskill HiTech 1.7.10

Одна самостоятельная программа [casino.lua](casino.lua): рулетка и слоты одновременно на экране, депозит и вывод предметов через PIM, отдельный сохраняемый баланс каждого игрока. Дополнительные Lua-библиотеки скачивать не нужно — используется OpenOS.

[Предпросмотр экрана](casino-preview.png) получен из тестовой модели GPU; это не скриншот с сервера Minecraft.

## Сборка

- Компьютер OpenComputers с процессором, RAM, HDD, EEPROM с BIOS и установленной OpenOS.
- Экран и видеокарта T3 рекомендуются. T2 поддерживается при разрешении 80×25; T1 не подходит.
- PIM из OpenPeripheralAddon, адаптер OC, транспозер, кабели и обычный сундук для кассы.
- Питание. Для круглосуточной работы должна быть прогружена вся конструкция.
- Карта данных **T2/T3 рекомендуется**: она предоставляет случайные байты. Без неё используется встроенный псевдослучайный `math.random`.

Разместите PIM непосредственно **над транспозером**, сундук — непосредственно **к востоку от транспозера**. Подключите адаптер к соседней стороне PIM. Соедините адаптер, транспозер, компьютер и экран кабелями OC.

```text
                 игрок
                   │
  адаптер ──────── PIM
      │            │
      └───── транспозер ── сундук (восток)
                │
             компьютер ── экран
```

Восток — направление мира Minecraft, не правая сторона при взгляде на экран. Числа сторон OC: низ `0`, верх `1`, север `2`, юг `3`, запад `4`, восток `5`.

Используйте один PIM у этого терминала. Адаптер должен читать **именно тот PIM**, который стоит над транспозером. Сделайте место перед экраном для одного игрока, чтобы другой игрок не мог подменить его на платформе во время обмена.

Касса, компьютер и адаптер должны находиться в закрытой части привата. К сундуку не подключайте трубы, воронки или другие устройства, меняющие содержимое. Предметы казино перемещает только эта программа.

## Установка и настройка

1. Перенесите содержимое `casino.lua` в файл `/home/casino.lua` на игровом компьютере. Через OpenOS можно открыть `edit /home/casino.lua` и вставить код из локального файла. При ограничении длины вставки вставляйте последовательными частями. Не вставляйте Markdown-ограждения из трёх обратных кавычек.
2. Настройки находятся в первых строках файла. По умолчанию:

   ```lua
   currency = "minecraft:emerald", damage = 0, coinsPerItem = 100,
   playerSide = "up", bankSide = "east",
   transposerAddress = nil, pimAddress = nil,
   minBet = 10, maxBet = 1000, maxExchange = 64,
   ```

   Принимаются обычные изумруды без NBT. Для другого предмета укажите его точный ID и metadata (`damage`). Проверка идёт по ID, а не по отображаемому имени. Валюта серверной команды `/money` не используется.

3. Выполните диагностику:

   ```text
   /home/casino.lua --list
   ```

   Она показывает адреса компонентов, стороны и размеры соседних инвентарей. Когда игрок стоит на PIM, его инвентарь обычно имеет 40 слотов. Программа работает только с 36 обычными слотами и не трогает броню. Имя рядом со стороной транспозера — имя **блока**, а не ник игрока.

   Если подключено несколько транспозеров или PIM, впишите полный адрес либо уникальное начало адреса в `transposerAddress` и `pimAddress`. Для этой установки всё равно используйте один игровой PIM, непосредственно примыкающий к выбранному транспозеру.

4. Положите в кассу стартовый запас изумрудов владельца. Депозит игрока увеличивает и кассу, и обязательства казино на одинаковую сумму. **Для выплаты выигрыша нужен дополнительный запас владельца.** Например, для ставки 10 coins на число запас сверх всех балансов должен составлять минимум 350 coins, то есть 4 изумруда при курсе 100. Для слотов при ставке 10 — минимум 240 coins, то есть 3 изумруда. Максимальная ставка на число 1000 требует дополнительного запаса 350 изумрудов.
5. Запустите:

   ```text
   /home/casino.lua
   ```

Публичный экран принимает нажатия только от игрока на PIM. Правый клик по поверхности экрана используется как нажатие. Программа включает инвертированный режим касаний; после выхода возвращает прежние настройки экрана. Если разрешение экрана менялось ранее, точный режим касаний также временно выключается.

**На время публичной работы уберите клавиатуру от экрана казино.** Посетителям нельзя предоставлять доступ к оболочке OpenOS: там можно остановить программу и менять её файлы. Для обслуживания сначала закройте доступ посетителям, затем подключите клавиатуру. Остановка — Ctrl+Alt+C. Не подключайте к сети казино чужие компьютеры; доступ к HDD и обслуживанию оставьте только владельцу.

Если нажатия других игроков не приходят, проверьте список пользователей компьютера: OC фильтрует события экрана, когда настроен список разрешённых пользователей. Для публичных касаний компьютер не должен быть ограничен только ником владельца; оболочку защищайте физически, как описано выше.

## Как играть

Игрок встаёт на PIM. Экран показывает его ник и сохранённый баланс. Общий баланс действует для обеих игр.

- «Депозит 1» / «Депозит 64» принимают до выбранного количества предметов. При нехватке предметов или места в кассе начисление идёт только за фактически принятые предметы.
- Ставка меняется кнопками `−10`, `+10`, `+100`, «Мин.». По умолчанию от 10 до 1000 coins.
- «Вывести 1» выдаёт один предмет за 100 coins. «Вывести 64» запрашивает до 64 предметов в пределах доступного баланса. Если свободного места или валюты в кассе меньше, списываются coins только за фактически выданные предметы.
- Остаток меньше стоимости одного предмета сохраняется на счёте.
- При смене игрока ставка и выбор рулетки сбрасываются. Чужие нажатия и нажатия других экранов игнорируются.

Баланс привязан к **нику Minecraft**, который возвращает PIM. Пароль вводить не нужно. При смене ника автоматического переноса счёта нет. UUID и события входа на PIM для этой версии не требуются: программа опрашивает текущего владельца платформы.

## Правила и выплаты

Все коэффициенты означают **общую выплату с учётом ставки**. Например, ставка 100 и выигрыш x2 дают выплату 200: итоговый прирост баланса — 100.

### Рулетка

37 равновероятных чисел от 0 до 36. Чётные числа 2–36 чёрные, нечётные 1–35 белые, 0 зелёный. Выберите цвет или конкретную ячейку, затем «Крутить рулетку».

| Ставка | Вероятность | Выплата |
|---|---|---|
| Чёрное / белое | 18/37 | x2 |
| Зелёное | 1/37 | x36 |
| Конкретное число, включая 0 | 1/37 | x36 |

Средний возврат — 36/37, примерно **97,30%**.

### Слоты

Три независимых барабана. На каждом равновероятно выпадает один из пяти символов: `A`, `B`, `C`, `$`, `7`. Коэффициенты находятся в `Core.triples` в коде.

| Комбинация | Выплата |
|---|---|
| Ровно два одинаковых символа в любых позициях | x1, возврат ставки |
| AAA | x3 |
| BBB | x5 |
| CCC | x8 |
| $$$ | x15 |
| 777 | x25 |
| Все три разные | x0 |

Тройка оплачивается один раз, без дополнительной выплаты за пару. Всего 125 равновероятных комбинаций; средний возврат — **92,8%**.

Результат записывается на диск **до анимации**. Остановка во время анимации не отменяет ставку и не даёт повторного броска. Вращение на экране — визуальный эффект; оно не изменяет шансы.

До ставки казино проверяет, покрывает ли касса сумму балансов **всех** игроков плюс максимальный возможный прирост по выбранной ставке. Если средств недостаточно, ставка не списывается. Владелец должен пополнить кассу или уменьшить максимальную ставку.

## Сохранение и восстановление

Данные хранятся на HDD в `/home/casino-data/ledger.log`. В журнал попадают подготовка обмена, фактически перемещённое количество, результаты игр и ручные сверки. Записи имеют номера и контрольную сумму. Это проверка повреждений, не защита от владельца, имеющего доступ к файлам.

Программа не сбрасывает баланс при повреждённом, пустом или оборванном журнале. Ошибка записи блокирует дальнейшие операции. Нельзя удалять журнал при существующих счетах или восстанавливать старую копию поверх действующего журнала: физические предметы уже могли быть выданы по более поздним операциям.

Для просмотра балансов и незавершённого обмена остановите программу и выполните:

```text
/home/casino.lua --audit
```

Если питание пропало между переносом предметов и записью результата, следующий запуск остановится. Автоматической повторной выдачи нет. `--audit` покажет `Pending` с ID (`seq`), игроком, направлением, количеством, слотами, исходными размерами стопок и адресами устройств.

После проверки реально перемещённого количества выполните:

```text
/home/casino.lua --resolve ID ФАКТИЧЕСКОЕ_КОЛИЧЕСТВО
```

Например, если операция `seq=17` реально переместила 3 предмета:

```text
/home/casino.lua --resolve 17 3
```

Эта команда **только исправляет учёт**, предметы не перемещает. Для депозита начисляет coins; для вывода списывает их. Если предметы точно не перемещались, укажите `0`. Один ID можно завершить только один раз. Не угадывайте число: сравните кассу/слоты с `sourceBefore` и `targetBefore`, сохраните копию журнала и выясните результат. При неизвестном результате оставьте казино остановленным до сверки.

При повреждении строки журнала `--resolve` также откажется работать. Восстановление повреждённого файла требует отдельной проверки операций и предметов, без автоматического игнорирования последних строк. Откат сервером мира/HDD не является атомарной транзакцией с инвентарями игроков; после такого отката требуется сверка.

Валюта, metadata и курс записаны в заголовке журнала. При их изменении существующее казино откажется запускаться, чтобы старые coins не получили другую стоимость. Лимиты ставок, размер экрана, адреса и стороны можно менять; при незавершённом обмене сначала выполните сверку исходных устройств.

Не запускайте две копии казино одновременно и не подключайте один журнал к нескольким компьютерам. Программа блокирует повторный запуск в общей среде OpenOS и проверяет размер журнала перед записью. Резервные копии делайте при остановленном казино.

## Проверка перед открытием

1. Положите в инвентарь один изумруд; депозит должен уменьшить его количество на один и дать 100 coins.
2. Остановите/запустите программу; баланс должен остаться 100.
3. Выведите один предмет; баланс должен стать 0, изумруд вернуться.
4. Повторите с другим игроком; счета должны быть раздельными, его касания не должны управлять вашим счётом.
5. Сделайте несколько ставок с небольшим стартовым запасом владельца. Проверьте отказы при нехватке баланса и резерва кассы.
6. Проверьте заполненную кассу и заполненный инвентарь. Coins должны изменяться только за фактическое перемещение.

Локальные автоматические тесты запускаются с Python и Lua 5.3 DLL:

```powershell
python tests/test_casino.py 'ПУТЬ\К\lua53-64.dll'
```

Они проверяют выплаты, перезапуск, два счёта, заполненные инвентари, неподходящие предметы, чужие касания, отказы записи и переноса, смену игрока, ручное восстановление и отрисовку 80×25/100×32. Проверки моделируют компоненты OC; работа на реальном MCskill ещё требует проверки в игре по шагам выше.
