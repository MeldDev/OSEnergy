# Монитор энергосети

`energy.lua` работает в OpenComputers и использует `average_counter.getAverage()`, как исходная версия. Все значения — EU/t. Нужны GPU и экран с разрешением минимум 60×22. На одном экране показаны пять категорий, общая выработка, общий расход, баланс и оценка производства материи. По умолчанию используется разрешение до 80×25 вместо максимального: на экране 160×50 текст становится крупнее. Размер можно изменить через `screenWidth` и `screenHeight`. График занимает максимум три строки; на экране высотой 22–23 строки он скрыт. На широком экране (от 100 столбцов) добавлены среднее за время работы и число доступных счётчиков.

## Настройка

1. Подключите отдельные `average_counter` на линиях генераторов и потребителей. Один счётчик может измерять всю категорию или отдельную независимую ветку. Единственный общий счётчик не позволяет разделить поток по типам устройств.
2. Выполните `energy.lua --list`, чтобы увидеть адреса счётчиков. Для определения соответствия линиям подключайте счётчики по одному и повторяйте команду.
3. Настройки находятся в начале `energy.lua`, в таблице `config`. Все пять адресов пользователя уже внесены. Для другой установки измените их:

   ```lua
   -- Фрагмент настроек адресов; остальные поля оставьте в файле.
   local config = {
     reactors = {"адрес-счётчика-реакторов"},
     solar = {"адрес-счётчика-солнечных-панелей"},
     wind = {"адрес-счётчика-ветрогенераторов"},
     molecular = {"адрес-счётчика-преобразователя"},
     machines = {"адрес-счётчика-механизмов"},
     updateInterval = 0.5
   }
   ```

   Можно использовать уникальное начало адреса и перечислить несколько счётчиков через запятую. Их показания суммируются. Не привязывайте один счётчик к нескольким категориям. Не суммируйте общий счётчик линии со счётчиками её ответвлений: это даст двойной учёт. Счётчик механизмов должен измерять расход без преобразователя, если преобразователь уже измеряется отдельно. Показания обоих типов потоков ожидаются положительными, как в исходной программе; отрицательные значения отмечаются как ошибка чтения.

4. Скопируйте только `energy.lua` в OpenComputers и запустите `energy.lua`. Отдельный файл настроек не нужен. После изменения настроек перезапустите монитор. Для выхода нажмите Q или Ctrl+C. Исходные разрешение и цвета экрана восстанавливаются.

Если настройка пустая и подключён ровно один счётчик, он отображается как реакторы для совместимости. При нескольких счётчиках нужна явная привязка. Список устройств обновляется каждый цикл, поэтому после восстановления соединения показания возвращаются автоматически.

## Значения на экране

- **Общая выработка** — сумма реакторов, солнечных панелей и ветрогенераторов.
- **Общий расход** — сумма преобразователя и механизмов.
- **Баланс** — выработка минус расход; показывается только при наличии данных всех пяти категорий.
- **`~`** — сумма только доступных настроенных счётчиков. Это неполные данные.
- **«не настроено»**, **«нет связи»**, **«ошибка чтения»**, **«неоднозначный адрес»** — отсутствие достоверных показаний, а не нулевая мощность.
- Среднее учитывает только полные успешные измерения. При неполных данных выработки в графике остаётся разрыв.

## Оценка материи

Под балансом идут две строки: **1 материя** (время производства) и **В минуту** (производительность в формате `n/M`, где `M` означает минуту). Значения рассчитываются по расходу категории `molecular`, независимо от доступности других категорий.

При цене 80 000 000 EU и 20 тиках в секунду время равно `80000000 / (EU/t × 20)` секунд, а производительность — `(EU/t × 20 × 60) / 80000000` материи в минуту. Например, 1 000 000 EU/t даёт около 4 секунд на материю и `15.00/M`. Это оценка при неизменном потоке, нормальном TPS и расходе всей измеренной энергии на материю, а не отсчёт до завершения текущей материи. При лаге сервера реальное время будет больше; `ticksPerSecond` можно изменить в настройках. Цена задаётся полем `energyPerMatter`.

При нулевом расходе показываются «нет питания» и `0/M`; при отсутствии полных показаний преобразователя — «нет полных данных».

Если категория физически отсутствует, оставьте её пустой: она будет отмечена как ненастроенная, сумма — как неполная, а баланс не будет рассчитан.
