# Сортировка книг OpenComputers + AE2

Программа `books.lua` рассчитана на OpenOS и API OpenComputers для Minecraft 1.7.10, используемый также в `energy.lua`.

Правила по умолчанию:

| Число разных чар | Действие |
| --- | --- |
| 1 | Сундук хранения, запад |
| 3 и больше | Сундук утилизации, восток |
| 2 | Оставить во входном сундуке |
| 0 или неизвестно | Оставить во входном сундуке |

«Прочность III» — один чар, а не три. Считаются разные чары, не сумма уровней. Обрабатываются только `minecraft:enchanted_book` и `minecraft:book`; инструменты, броня и другие предметы не перемещаются. Если сборка не отдаёт список чар, книга остаётся на входе. Обычная книга с отсутствующим списком и `hasTag=false` считается книгой без чар; для зачарованной книги отсутствие списка означает неизвестное число.

## Что поставить

- Работающий компьютер OpenComputers с OpenOS, экраном, клавиатурой и питанием.
- Один **Transposer / Транспозер** OpenComputers, соединённый с компьютером кабелем OC.
- Три отдельных сундука вплотную к транспозеру: сверху вход, на западе хранение, на востоке утилизация. Для боковых сундуков удобны одиночные: они не должны объединяться с соседними.
- Шина экспорта AE2, установленная на входном сундуке и подключённая кабелем AE2 к вашей сети.
- Для `--network`: адаптер OC вплотную к МЭ-контроллеру или МЭ-интерфейсу и кабель OC от адаптера к компьютеру. Этот адаптер нужен для просмотра сети; сортировка работает через транспозер независимо от него.

Схема, вид сбоку по линии запад–восток:

```text
                  [ВХОДНОЙ СУНДУК] <- шина экспорта <- МЭ-сеть
                          |
 [ХРАНЕНИЕ, запад] — [ТРАНСПОЗЕР] — [УТИЛИЗАЦИЯ, восток]
                          |
                  кабель OC к компьютеру
```

Стороны `up/west/east` относятся к транспозеру. Запад и восток определяются по F3, а не по направлению взгляда игрока. В `config` в начале файла можно задать другие стороны: `up`, `down`, `north`, `south`, `west`, `east`. Вход и два выхода должны быть разными.

Для подачи разных зачарованных книг настройте фильтр шины экспорта на зачарованную книгу и установите **карту нечёткости / Fuzzy Card**, чтобы шина не ограничилась NBT конкретной книги. На вашей версии AE2 сначала проверьте подачу двух книг с разными чарами. Без нечёткого сравнения шина может экспортировать только точный образец. Для проверки самой программы книги можно положить во входной сундук вручную. Не включайте изготовление недостающих книг в шине.

Сундук утилизации — обычный выход: сама программа предметы не уничтожает. После проверки можно подключить к нему вашу систему уничтожения. Сундуки выхода не должны импортироваться обратно в эту же сортировку. Не подключайте к сундукам сортировщика МЭ-шину хранения: сортировщик должен видеть физические книги в сундуке, а МЭ не должна забирать их параллельно.

## Запуск

1. Скопируйте `books.lua` в `/home/books.lua` компьютера OpenComputers.
2. Выполните `books --list`. При нескольких транспозерах задайте адрес или однозначный префикс в `transposerAddress`. При нескольких МЭ-компонентах задайте `aeAddress`. Пустая строка допустима, только если подходящий компонент один.
3. Если подключён адаптер МЭ, выполните `books --network`: увидите количество чар у книг сети. Эта команда только читает сеть и не требует транспозера.
4. Пока отключите автоматическую подачу книг. Положите во входной сундук тестовые книги с 1, 2 и 3 чарами. Выполните `books --check`. Команда проверит наличие всех трёх сундуков и покажет назначение каждой книги **без перемещения**.
5. Выполните `books --once`. Проверьте: 1 чар — запад, 3+ — восток, 2 — остались сверху. Затем включите подачу и запустите `books --run`.

Остановка — Ctrl+C. Интервал между проходами — `interval = 3` секунды. За проход программа пытается перенести по одной книге из каждого подходящего слота. При заполненном выходе книга остаётся на входе, следующая попытка — в следующем проходе. При потере инвентаря или ошибке API программа останавливается с сообщением; после исправления запустите её снова.

Книги с двумя чарами, обычные книги, неизвестные книги и посторонние предметы занимают входной сундук. Их нужно периодически вынимать; заполненный вход остановит экспорт новых книг. Не возвращайте оставленные книги автоматическим импортом в ту же сеть: получится круговорот. Для запуска сортировки при загрузке добавьте `/home/books.lua --run` в `/home/.shrc` после проверки всей схемы.

Если появляется `not enabled in config`, сервер запрещает чтение предметов через OC: администратору нужно проверить `allowItemStackInspection`. Сырой NBT и `allowItemStackNBTTags` для программы не нужны. Если у заведомо зачарованных книг показано `?`, сортировать их нельзя до выяснения API конкретной сборки.

## Основание API и проверка

Использованы штатные интерфейсы OpenComputers: [чтение МЭ-сети](https://github.com/MightyPirates/OpenComputers/blob/master-MC1.7.10/src/main/scala/li/cil/oc/integration/appeng/NetworkControl.scala), [список enchantments у предметов](https://github.com/MightyPirates/OpenComputers/blob/master-MC1.7.10/src/main/scala/li/cil/oc/integration/vanilla/ConverterItemStack.scala), [чтение внешнего инвентаря](https://github.com/MightyPirates/OpenComputers/blob/master-MC1.7.10/src/main/scala/li/cil/oc/server/component/traits/WorldInventoryAnalytics.scala), [перенос между инвентарями](https://github.com/MightyPirates/OpenComputers/blob/master-MC1.7.10/src/main/scala/li/cil/oc/server/component/traits/InventoryTransfer.scala).

Автоматические тесты: `python tests/test_books.py` (нужен Python с пакетом `lupa`). Они имитируют компоненты OpenComputers и выполняются на Lua 5.2 и 5.3; проверка в вашей игровой сборке выполняется командами выше.
